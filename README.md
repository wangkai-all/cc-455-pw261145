# 分片下载控制台

可恢复的大文件分片下载器：逐片校验和、并发下载、断点续传、版本替换感知，以及合并前的整体
SHA-256 验证。附带一个可注入故障的演示服务端和实时仪表盘。

零运行时依赖：服务端用 Node 内置 `http`，浏览器端是原生 ES 模块。

## 快速开始

```bash
npm start            # http://127.0.0.1:4173
```

```bash
npm test             # 单元测试 + 引擎/服务端集成测试
npm run test:e2e     # Chromium 端到端测试（需要可启动的浏览器）
```

`PORT` / `HOST` 环境变量可覆盖监听地址。

## 它解决什么问题

普通 `fetch → blob` 下载在大文件上会失败于四类现实问题，这个项目对每一类都有明确处理：

| 问题 | 处理方式 |
| --- | --- |
| 网络中断、连接被重置 | 每个分片独立重试，指数退避 + 抖动，原因写入重试日志 |
| 分片内容损坏 | 落盘前逐个比对清单里的 SHA-256，不匹配即重下 |
| 服务端返回的范围与请求不一致 | 校验 HTTP 状态、`Content-Range` 起点/终点/总长度、`Content-Length` 与响应体长度，任一项对不上就判定为「范围响应不一致」 |
| 下载途中文件被替换 | 轮询版本 + 服务端 409 + 合并前再确认一次；旧分片按校验和决定复用或废弃 |

此外：取消、暂停、关闭页面后重新打开都能从已完成分片继续，恢复时会**重新计算已存分片的哈希**
再复用，而不是盲信本地状态。

## 使用仪表盘

1. 顶部标签切换文件，左栏是当前文件的下载面板。
2. 「开始下载」启动；「暂停」「取消」会保留已完成分片；「清除本地分片」删除该文件全部本地数据。
3. 并发数滑块可在下载过程中调整，调度器会立即补位或收缩。
4. 分片网格每个方块是一个分片，悬停或键盘聚焦可看字节范围、校验和、尝试次数与最近一次失败原因；
   切到「表格」视图可看到全部分片的哈希。
5. 右栏「故障注入」实时生效：断网、连接中断、分片损坏、范围错位、基础延迟。
6. 「替换文件（发布新修订）」立即发布新版本，正在进行的下载会收到 409 并切换到新清单。

## 故障注入的行为

- **模拟断网**：分片请求返回 503，客户端按「连接失败」重试；达到上限后进入失败状态，
  已完成分片保留，恢复网络后点「继续下载」即可。
- **连接中断**：先声明完整 `Content-Length`，再在响应体中途销毁 socket。
- **分片损坏**：翻转响应体中的一个字节，长度与范围都合法，只有哈希能发现。
- **范围错位**：返回一段偏移错误的字节，但 `Content-Range` 谎称是请求的范围。
  客户端同时校验头部与哈希，因此会被识别为「范围响应不一致」或在哈希处被拦下。
- **文件替换**：新修订总是改写第 0 页及每第 13 页，并在末尾追加 1–2 MiB。
  下载器用清单逐片比对校验和，复用未变化的块（网格里带右下角缺角标记），其余作废重下。

## 正确性边界

- **逐片校验在前，整体校验在后。** 每片落盘前比对哈希；合并后用流式 SHA-256 再算一次整文件哈希，
  与清单不一致则判定失败（`hash-mismatch`），分片保留以便重试。
- **恢复不是盲信。** IndexedDB 里的状态只当线索：分片数量对不上、或哈希不符，都会被丢弃并重下。
- **替换后复用要过校验和。** 替换发生时，旧状态中哈希与新清单一致的索引才保留；
  `manifest` 的 `versionHistory` 记录每次替换复用了多少、作废多少。
- **中止是协作式的。** 暂停/取消会 abort 在途请求，等待当前运行循环收尾后才落状态，
  因此暂停后立即关页面也不会留下半写状态。

## 目录结构

```
server/
  catalog.js      确定性内容生成 + 分片清单（含整文件与逐片 SHA-256）
  index.js        HTTP 服务：清单、分片 Range、SSE 事件、故障注入、版本替换
public/
  lib/sha256.js   可增量喂入的 SHA-256（浏览器与 Node 通用）
  lib/store.js    IndexedDB / 内存存储，分片以 Blob 独立存储
  lib/engine.js   下载引擎：并发、重试、校验、恢复、版本协调、合并校验
  app.js          仪表盘控制器（keyed diff 渲染分片网格）
  styles.css      浅色/深色主题与图表标记
test/
  unit.test.js    SHA-256、内容生成、存储
  api.test.js     引擎 + 真实服务端：四类故障、取消恢复、替换、并发上限
  e2e.test.js     Chromium：故障下载、暂停重开恢复、热替换、断网耗尽后恢复
scripts/
  screenshots.mjs 对运行中的服务端抓取各类状态的截图
```

## 在最小容器里跑端到端测试

Playwright 的 Chromium 需要系统库和字体。若 `npm run test:e2e` 报
`error while loading shared libraries` 或截图里文字全空，把依赖装到一个私有目录，
再用环境变量指过去（无需 root）：

```bash
apt-get -o Dir::State::lists=/tmp/apt/lists ... download libglib2.0-0 libnss3 ... fonts-noto-cjk
for f in *.deb; do dpkg-deb -x "$f" /tmp/sysroot; done

export LD_LIBRARY_PATH=/tmp/sysroot/usr/lib/x86_64-linux-gnu:/tmp/sysroot/lib/x86_64-linux-gnu
export FONTCONFIG_PATH=/tmp/sysroot/etc/fonts
export XDG_DATA_HOME=/tmp/sysroot/usr/share   # 让 fontconfig 找到 Noto CJK
npm run test:e2e
```

## 实现说明

- **分片地址**：`GET /api/files/:id/chunk/:index?rev=N`，带 `Range: bytes=start-end`
  （文件级偏移）。服务端返回 206 与对应的 `Content-Range`。
- **完整下载流程**：客户端总是按清单逐片请求，不使用整文件流；`/content` 端点仅用于抽查。
- **版本协商**：请求带 `?rev=`。若服务端已是更新修订，返回 409 及新清单摘要；
  客户端另有 4 秒轮询作为兜底，避免只在替换瞬间路过才被发现。
- **SSE**：`/api/events` 推送故障、配置与替换事件，仅用于界面提示，不参与下载正确性。
- **演示规模**：文件 24–96 MiB，分片 512 KiB–2 MiB，便于在几秒内跑完一次带故障的下载。
